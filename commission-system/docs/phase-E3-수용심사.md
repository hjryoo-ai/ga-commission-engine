## 1. 인정하는 것

- **E1의 증명 방식.** 정책 픽스처 2개를 같은 JVM·같은 컴파일 결과로 돌리고, 프로덕션 소스에 임계치·라벨·코드·사유 문자열이 리터럴로 없음을 스캔 테스트(주입 I3로 작동 확인)로 못 박았다. "룰=데이터"를 엔진에서도 같은 형식으로 증명했다.
- **`unavailableReasons`를 목록에서 맵으로 바꾼 판단(§5-3).** 목록이면 `"NO_RATE_DATA"` 문자열이 코드에 남는다는 것을 알아채고 원인(닫힌 enum)과 응답 문자열(데이터)을 분리했다. 지시문의 예시가 규칙과 충돌하는 지점을 잡아 고친 것이다.
- **`commission-disclosure` 모듈 신설(§5-2).** 계획대로 `commission-api` 패키지에 두면 infra가 웹 모듈에 의존하게 된다는 이유가 맞다.
- **주입 기록의 자기 정정(§8).** 첫 배치의 I8·I9가 잘못된 주입이었음을 기록하고 다시 한 것. "잡히지 않음"을 그대로 두지 않고 원인을 밝힌 기록이 이 표의 신뢰를 만든다.
- **JCS를 직접 쓴 결정.** `platform-canonical`이 Java 25 바이트코드라 Java 21 엔진이 쓸 수 없다는 사실을 먼저 확인했다. 두 저장소가 같은 RFC 8785 구현체를 쓰는지는 E3.1에서 테스트 벡터 파일을 공유해 확인한다(§3-6).

## 3. E3.1 후속 PR 항목

1. **UPSTREAM → `ga-disclosure` 계약 1.2.0 병합 커밋.** `contracts/` 복사본·CHECKSUMS 재검사.
2. **상품 키 규칙 반영.** 3A 계획 Q1 결정(아래 회신)대로 `^[A-Z0-9][A-Z0-9-]{0,7}:[A-Za-z0-9][A-Za-z0-9._-]{0,30}$`, 40자. 요청 검증(400)과 `DISC_PRODUCT_GROUP_MEMBER` 외부 키 컬럼 폭 40.
3. **계약 변경 요청 4(GET 403):** 설명을 "토큰은 유효하나 인가 거부(역할 없음). 다른 테넌트의 스냅샷은 404"로 바꾼다. 응답 형태는 그대로. 1~3(추가형)과 함께 1.2.0에 포함 — `ga-disclosure` 계약 PR 담당.
4. **채번 경합 제거.** 일자별 카운터 테이블 대신 **Oracle SEQUENCE** 하나를 쓴다. `snapshot_id`는 `GRD-{yyyyMMdd}-{seq}`에서 뒤 숫자를 날마다 0부터 다시 세지 않는다(계약은 형식만 정하고 일자별 재시작을 요구하지 않는다). 경합·재시도·MERGE가 전부 사라진다. 테스트: 같은 순간 발급 50건 실패 0, ID 유일.
5. **`CLAUDE.md` 신설.** CONTRIBUTING.md와 설계서 부록 B의 규약을 `ga-disclosure` CLAUDE.md와 같은 구조(절대 규칙·코드 규약·작업 방식·면책)로 옮긴다. 내용을 새로 만들지 말고 있는 규약을 모은다.
6. **JCS 상호 검증.** `ga-disclosure`의 `platform-canonical` 테스트 벡터 파일(`src/test/resources/jcs/`)을 복사해 엔진의 JCS 구현이 같은 출력을 내는지 테스트. 두 저장소가 같은 바이트를 만들지 않으면 봉인 해시 대사가 깨진다.

## 4. §9 질문에 대한 결정

1. **등급 판정 기준 비율: 반올림 비율(현행) 확정.** 근거는 §2-6.
2. **정책·상품군 데이터의 운영 경로.** 정책(`DISC_GRADING_POLICY`·`DISC_RANKING_POLICY`)은 엔진이 요율·시책에 쓰는 **기존 룰 버전 승인 흐름을 재사용**한다(DRAFT→APPROVED→ACTIVE, 변경 감사, Phase 16의 승인 러너). 관리 API는 만들지 않는다. 상품군 정의·소속은 `ga-disclosure` 카탈로그(Phase 2)와 **같은 파일 형식**(`contracts/catalog/v1/product-groups.schema.json`, `ga-disclosure`가 정의)에서 수입하고, 외부 키→원장 키 매핑은 엔진 측 데이터 파일로 둔다(정확히 일치하는 `insurer_cd`·`product_key`만 매핑, 추측 없음 — 지금 방식 유지). 이 작업은 E3.1이 아니라 **E4**(별도 지시)로 미룬다. 지금은 SQL 시드로 충분하다.
3. **비교공시 경로의 3분위 등급 → 같은 데이터 정책으로 옮기는 것은 서식 확정 시.** §11 #13에 한 줄로 남기고 지금은 손대지 않는다.
4. **서비스 토큰 운영.** 토큰은 256비트 난수, 엔진은 SHA-256만 보관(현행). **회전**: 엔진 설정이 해시 **목록**을 받아 겹침 기간에 현재·다음 두 개를 인정한다(E3.1). `ga-disclosure` 쪽 보관은 3A에서는 **설정 기반 포트**(`EngineCredentialPort`, 테넌트별 환경 설정)로 두고, Phase 8 운영 조립에서 Phase 2 볼트(테넌트 DEK, AAD=`tenant_id`·`engine_token`)로 옮긴다. mTLS는 §14 그대로 미결정.
5. **채번 경합: 엔진이 없앤다.** §3-4(SEQUENCE).
6. **UPSTREAM: 병합 커밋.** §3-1.
